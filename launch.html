SurveyGuard: test survey console

1. Suppliers

Who sends respondents, how each one names its respondent id, and where each ending goes. [RID] in a URL is replaced with the respondent id. A relative URL is read against the survey. An ending left empty stays on the survey's own end page (security falls back to terminate).

Saved in this browser only: the survey uses this list for respondents who open it here. Respondents on other devices (a deployed survey) get assets/config.js's list: export this one and paste it over suppliers there. Register the same codes and URLs in the dashboard (Suppliers) too: after the decoy, the server sends a respondent to its record's security URL.

2. Go straight to the survey (SDK only)

One entry link per supplier, as the supplier would send a respondent: its code in src, its respondent id in its own parameter. Each click is a new respondent. 3. Through the lobby

Lobby links are signed by the server, so this page cannot make one. Generate one per supplier in the dashboard (Projects → the lobby project → Links), choosing the supplier, with that supplier's target URL below, and paste it here. A respondent the lobby blocks goes to the link's terminate URL: the supplier's security URL in the dashboard, unless you give one.
